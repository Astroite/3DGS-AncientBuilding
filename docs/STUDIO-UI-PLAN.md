# GS Studio：UI 风格探索计划

## 当前约束

用户于 2026-09-13 补充：不运行 CPU/GPU 测试，不干扰其他会话任务，并将 UI 风格探索加入开发计划。

后续不启动训练、基准测试、回归测试或应用验证程序。此前已完成的验证记录保留；尚未完成的验证保持待验收，只有用户另行明确要求后才恢复。视觉探索先通过静态设计稿推进。

现有 Tk 界面是功能原型，不能视为正式产品 UI。视觉方案确定前，不继续围绕现有控件外观做零散美化。

## 目标与顺序

将 UI 风格探索列为 P0 设计工作，安排在正式界面细化之前：

1. 梳理导入、训练、检查、编辑、导出五个阶段的信息优先级。
2. 提供三套差异明确的静态视觉方案，使用相同内容和窗口尺寸便于比较。
3. 用户选定方向后，统一设计规范并展开关键状态。
4. 按选定方案完善正式 UI；运行验证仍受上述约束，不自动启动。

本阶段不决定更换 UI 框架或训练架构，也不修改正在运行的其他任务。

## 三个探索方向

| 方向 | 视觉与布局 | 重点 |
| --- | --- | --- |
| A：深色专业工作台 | 中性石墨灰、克制的青绿色强调、紧凑工具栏、可折叠侧栏 | 以三维视口为中心，适合长时间检查与精细编辑 |
| B：极简创作工具 | 温和浅色背景、清晰字体、大留白、少量浮动工具 | 减少参数压力，让导入到产出的操作路径直观 |
| C：影像检查工作台 | 深色影像画布、紧凑图片条、源图与渲染并排、集中训练状态 | 强化画质对照、相机定位与训练中的问题判断 |

三套方案不能仅更换主题色：需要呈现不同的信息密度、面板组织和主要操作位置。

## 每套方案的交付内容

- **主工作台设计稿**：同一场景、同一组训练信息，展示视口、图片导航、训练状态与操作。
- **导入检查设计稿**：目录选择、模型选择、匹配统计、遮罩说明、错误定位及开始入口。
- **设计说明**：字体层级、颜色角色、间距、边框、图标、选中状态和主要按钮样式。
- **取舍说明**：适合的工作方式、信息密度以及小窗口下的收缩策略。

静态稿中的进度、损失和模型画面必须标注为示意，不表示实际运行或验证结果。

## 正式设计必须解决的问题

- 三维视口占据视觉中心；侧栏不挤压主要工作区域。
- 路径输入、训练参数与编辑工具按当前阶段组织，避免所有字段同时堆放。
- “开始新实验”“暂停/继续”“保存项目”“保存检查点”“导出”职责和层级明确。
- 训练状态与错误信息清晰，不依赖颜色单独传达含义。
- 源图和渲染提供足够大的对照区域，保持对应视角与同步缩放；不将源图缩成难以检查的小缩略图。
- 图片名称、训练/验证分组、遮罩极性和未匹配数量易读；长路径有合适的截断与完整查看方式。
- 模型编辑的选区、裁剪框、变换反馈、撤销重做与导出结果一目了然。
- 基础操作优先呈现；SH、检查点间隔等高级参数渐进展开。
- 为等待 GPU、暂停、失败、恢复、导入错误和空项目设计完整状态；GPU 等待不显示为训练中。
- 兼顾 Windows 中文字体、1280×800 与 1920×1080 布局，以及较高显示缩放比例。

## 方案确定标准

用户能直接比较三套方案并选定主方向；选定后产出一套完整的颜色、字体、间距、组件和状态规范。正式 UI 实现沿用该规范，不让后续开发自行拼凑样式。

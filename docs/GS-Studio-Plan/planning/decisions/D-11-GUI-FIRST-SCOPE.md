# D-11：APP 原位升级为全流程 GUI 产品

- 日期：2026-09-22
- 状态：已接受；产品目标尚未实现或验收
- 决定者与依据：用户确认全流程统一 GUI、APP 原位升级、CLI 兼容保留，并选择新 GUI 实验默认 gsplat。
- 关联需求和任务：原 I/T/V/E/O、UI、NFR；新增 C/R/Q/G 与 AC-17～20 见 [APP 项目路线图](../../../GS-STUDIO-PROJECT-ROADMAP.md)。
- 替代的既有决定：扩展 D-01 的原下游首版范围；不撤销已通过评审的 A 方向设计。

## 要解决的问题

旧规划从 RealityScan 输出开始，APP 实际还负责采集登记、Run、重建与 QA。产品需要统一日常入口，同时保留历史 Run 和脚本的可用性。

## 可行选项

| 选项 | 取舍 |
| --- | --- |
| APP 原位升级，全流程 GUI 为默认 | 统一项目体验，并可复用现行服务与历史清单；需要补充上游 GUI 设计和工程整合 |
| 仅扩展下游训练工作台 | 投入较小，但不能覆盖用户要求的日常全流程 |
| 新建应用仓库并迁移 APP | 可重新组织代码，但增加目录、环境和历史兼容迁移成本 |

## 决定与理由

APP 的仓库和目录保持不变，用户可见产品统一为 GS-Studio。GUI 最终覆盖地点、场景、Capture、Run、重建、QA、训练、编辑和导出。`gsdb` CLI 留作脚本、恢复和历史兼容入口；业务规则由 GUI 与 CLI 共用。首次安装、底层诊断和应急恢复可继续使用脚本/CLI。

新 GUI 实验预选 **gsplat**，同时提供 Postshot 选择；现行 CLI `train --segment` 仍默认 Postshot，schema 6 当前配置及旧 Run 的读取/恢复行为保持不变。GUI 必须把后端明确写入新实验，不借产品命名暗改已有配置。此项是未来 GUI 的交互默认，不表示现有 CLI 默认已变或当前产品已验收。

## 后续影响

现行里程碑、入口映射与验收编号在 APP 两份路线图中维护。A 方向静态设计继续作为重建后工作台基线，上游页面与状态另行设计。只有正式 GUI 具备能力并完成相应验收后，才把操作手册的日常入口切换至 GUI；当前手册继续描述真实可用流程。D-02 的运行验证暂停约束继续有效。

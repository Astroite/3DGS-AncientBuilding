## 同条件画质比较方式

比较包含两个视角：固定共同输入与相机下的最终可交付质量，以及各路线合理配置下的质量/资源取舍。不同策略的“同一步数”不代表同预算；记录完整运行耗时和预算，不把它直接作为公平性能标尺。抗锯齿、SH、分辨率、背景、曝光显示、补偿及训练区域需要说明差异。

分别保留已知相机拟合、验证视角和自由新视角观察；查看器额外曝光/PPISP 处理单独标记。若未来采用 PSNR/SSIM/LPIPS，应固定实现版本、遮罩支持及比较区域，不为提高分数把验证图加入训练或独立拟合验证曝光而不告知。没有预先批准的指标阈值时不发明“达标分数”。

人物残留与高亮不是单个平均指标能充分反映的内容，应记录同视角局部细节及用户判断。全景组应保持隔离，避免邻接切面泄漏造成虚高结果。PLY 需要在独立消费者中看方向相关颜色，而不仅是静态正面截图。

## 先验证哪些假设

1. **最先：VH-01～03 输入与损失。** 如果分组或遮罩不正确，后续画质比较无效。主路线的周期 split、缺点降级及 Brush 的 mask resize 是明确需关闭或改造的路径。
2. **接着：VH-04/05/07/12 的小范围质量、恢复与交付。** 在大量 UI 工程投入前确认推荐前提。只跑通极短训练不能通过画质验收。
3. **再做：VH-09～11 的训练/预览/独立快照资源协作。** 根据实际输入规模记录 CPU 帧复制、GPU 上传、模型副本与更新频率的开销，判据由 D-08 补充。
4. **最后覆盖：VH-06/08/13/14 与正式交付。** 包括异常状态、项目恢复、DPI、离线和打包。设计稿获认可不能替代这些运行证据。

## 路线决策如何使用结果

- 输入污染、无法恢复有效检查点、编辑污染训练、PLY SH/方向错误是阻断项；先修复再谈画质优势。
- 同条件下可交付质量持续明显退化且合理配置不能解决，可推翻 LichtFeld 主推荐；退回 Python/gsplat 前同样验证其改造后的目标版本。
- 较重依赖或较多 UI 工作本身不压过画质优先，但无法在允许的隔离环境构建或维护会触发备选。
- D-08 数值阈值、D-06 缺失分组规则、D-07 非穿透定义仍需决策，不能由验证者暗中制定。
- 报告应写清通过、失败、阻断或未执行，附版本与实际输出身份。“有文件”“窗口打开”“检查点按钮可点”都不能替代训练成功。

# GSDB v0.2 多输入与质量门禁

v0.2 把所有新输入规范化为一组 2:1 JPEG 候选帧，再复用同一套投影、遮罩、
COLMAP 和训练链路。规范输入位于
`prepared/<capture-id>/<preparation-hash>/dataset.json`；它是可重建缓存，
原始素材仍按只读来源处理。

旧 schema 1 capture 和旧 run 不会自动升级，原有 `ingest` / `preprocess` 命令
仍可照常使用。

## 教程一：Insta360 Studio 导出的 2:1 视频

新项目可以把 Studio 导出的 2:1 文件直接登记为 schema 2：

```powershell
.\gsdb.ps1 capture init LOCATION SCENE CAPTURE `
  --source-type equirect_video `
  --source 'D:\Media\capture-equirect.mp4' `
  --camera-model X6

.\gsdb.ps1 media probe LOCATION SCENE CAPTURE
.\gsdb.ps1 preprocess LOCATION SCENE CAPTURE
```

X6 已可直接走教程三的 `insta360_insv` 路径（MediaSDK 已用真实 X6 素材验证），
不再要求经过本教程。v0.2 仍不对任何型号的 INSV 做 FFmpeg 双鱼眼降级或格式逆向。

## 教程二：2:1 图片序列

目录内图片应统一尺寸并使用带数字索引的文件名。无数字索引时必须显式给
`--fps`；建议所有序列都写明真实 FPS，以获得正确时间戳。

```powershell
.\gsdb.ps1 capture init LOCATION SCENE CAPTURE `
  --source-type equirect_sequence `
  --source 'D:\Media\panorama-frames' `
  --fps 29.97 `
  --camera-model X5

.\gsdb.ps1 preprocess LOCATION SCENE CAPTURE
```

也可多次写 `--source` 显式列出文件。GSDB 会拒绝尺寸不一致、非 2:1、重复
数字索引或无法解码的图片。

## 教程三：MediaSDK INSV

仓库不分发 Insta360 的 DLL、头文件、模型或许可文件。SDK 获批并解压后，在
Windows PowerShell 设置：

```powershell
$env:INSTA360_MEDIA_SDK_ROOT = 'D:\Project\3DGS\APP\sdks\Insta360-MediaSDK'
# 先按获批 SDK 包内头文件/API 完成 insta360_bridge.cpp 并链接 SDK。
& .\tools\mediasdk-helper\build.ps1
$env:GSDB_MEDIA_HELPER = 'D:\Project\3DGS\tools\mediasdk-helper\build\Release\gsdb-media-helper.exe'
.\gsdb.ps1 doctor --require mediasdk
```

`gsdb.ps1` 通过 `WSLENV` 转发这两个路径。helper 必须是 Windows x64 程序；
JSON 请求、响应和输出缓存放在 Windows 项目盘上，不把 WSL ext4 或 UNC 路径
传给 SDK。当前仓库提供完整协议边界和 CI fake helper；获批包的头文件/API
版本到手后，需要按包内 Windows `main.cc` 完成
`tools/mediasdk-helper/src/insta360_bridge.cpp` 的专有适配并执行硬件验收。
仓库当前 C++ bridge 是会返回 `sdk_adapter_not_linked` 的协议桩，不应将它描述为
已经具备生产 INSV 直读能力。完整 JSON 字段契约见
`tools/mediasdk-helper/README.md`。

单双文件都必须显式列出，不会根据 `_00_` 猜 `_10_`：

```powershell
.\gsdb.ps1 capture init LOCATION SCENE CAPTURE `
  --source-type insta360_insv `
  --source 'D:\Media\VID_..._00_001.insv' `
  --source 'D:\Media\VID_..._10_001.insv' `
  --camera-model X5

.\gsdb.ps1 media probe LOCATION SCENE CAPTURE
.\gsdb.ps1 preprocess LOCATION SCENE CAPTURE

# 用真实 SDK/素材完成 probe、指定帧导出、2:1、数量和逐帧哈希验收：
.\scripts\test-mediasdk-helper.ps1 `
  -LocationId LOCATION -SceneId SCENE -CaptureId CAPTURE
```

helper 只接收本次均匀选出的候选帧号，并通过 `SetExportFrameSequence` 配合
`SetImageSequenceInfo` 输出，默认正好 270 张。参数固定为 Dynamic Stitching、
FlowState 开、Direction Lock 关、AI 降噪/锐化/调色关。支持型号基线为 ONE X、
ONE R/RS、ONE X2、X3、X4、X4 Air、X5、X6；最终以获批 SDK 的 capabilities 和
真实样本为准。

## 遮罩审核与训练门禁

新 v3 run 在 `mask` 后必须冻结遮罩集合：

```powershell
.\gsdb.ps1 mask LOCATION SCENE RUN_ID
.\gsdb.ps1 mask-review LOCATION SCENE RUN_ID --attempt primary
.\gsdb.ps1 mask-finalize LOCATION SCENE RUN_ID --attempt primary
.\gsdb.ps1 reconstruct LOCATION SCENE RUN_ID
```

`unreviewed` 和 `ok` 允许继续；`false_positive`、`false_negative`、mask SHA
变化造成的 `stale` 会阻断。`exclude` 会写入带哈希的不可变清单，并从 COLMAP
image list、同帧 pairs 和最终训练输入中排除。

如果 primary 低于注册率/覆盖率门槛，命令会生成 fallback 图片与遮罩并把 run
置为 `waiting_review`。之后执行：

```powershell
.\gsdb.ps1 mask-review LOCATION SCENE RUN_ID --attempt fallback
.\gsdb.ps1 mask-finalize LOCATION SCENE RUN_ID --attempt fallback
.\gsdb.ps1 reconstruct LOCATION SCENE RUN_ID --resume
```

rig BA 后会在选中数据集内写 `trajectory-qa.json` 和 `trajectory-top.svg`。
非有限位姿、时间倒序、重复帧和超过非零中位步长 10 倍的 teleport 会阻止
Splatfacto 与 Postshot；远时间近位置只记录为可能回环。

动态类别默认只有 `person`，可在新 run 创建时增加：

```powershell
.\gsdb.ps1 preprocess LOCATION SCENE CAPTURE `
  --mask-classes person,car,bus,truck,bicycle,motorcycle
```

## 可选 COLMAP 回环

回环默认关闭，且从不联网下载 vocabulary tree：

```powershell
.\gsdb.ps1 preprocess LOCATION SCENE CAPTURE `
  --loop-closure `
  --vocabulary-tree 'D:\Models\colmap-vocab-tree.bin' `
  --loop-period 20 `
  --loop-num-images 5
```

词汇树 SHA-256 会进入 run 配置；文件改变后拒绝续作。

## Postshot 一键训练

先整理最终已注册数据，再检查完整命令：

```powershell
.\gsdb.ps1 doctor --require postshot
.\gsdb.ps1 postshot-prepare LOCATION SCENE RUN_ID
.\gsdb.ps1 postshot-train LOCATION SCENE RUN_ID --dry-run
.\gsdb.ps1 postshot-train LOCATION SCENE RUN_ID
```

默认把 Postshot 数据集整理到 `<run-id>/postshot/`，训练输出写到
`<run-id>/postshot-training/model.psht`，都在 run 目录内，不再区分独立的
`work/`/`inputs/` 子树。自定义整理目录时，训练端必须显式使用同一目录：

```powershell
.\gsdb.ps1 postshot-prepare LOCATION SCENE RUN_ID --output 'D:\GSDB-Postshot\dataset'
.\gsdb.ps1 postshot-train LOCATION SCENE RUN_ID --dataset 'D:\GSDB-Postshot\dataset' --dry-run
```

默认使用 Postshot 1.1.69+、Splat3、导入 COLMAP poses、全部图片、occluder
masks、原始分辨率和 training context，输出
`<run-id>/postshot-training/model.psht`。可用 `--profile`、`--ksteps`、
`--max-splats`、`--gpu`、`--output`、`--export-ply`、`--export-spz` 覆盖。
Postshot 1.1.69 的单次训练只接受一个 `--export-splat`，因此 PLY 与 SPZ 选项
互斥；`--output` 必须以 `.psht` 结尾，两个导出选项也分别要求 `.ply` 与
`.spz` 后缀。可用显存低于 8 GiB 时需显式传 `--allow-low-vram`。

默认项目旁写入 `postshot-train.log` 和 `training.json`；自定义项目名
`NAME.psht` 使用 `NAME.postshot-train.log` 与 `NAME.training.json`，避免同目录训练
互相覆盖。清单在成功或失败时都会记录命令、Postshot 版本、数据集血缘、GPU
峰值和已产生项目/导出的 SHA-256。

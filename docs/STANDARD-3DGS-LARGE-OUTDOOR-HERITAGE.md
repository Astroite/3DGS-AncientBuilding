# GSDB 大范围室外古建筑 3DGS 工作规范

- 版本：0.1.0
- 日期：2026-08-29
- 状态：项目建议规范（Draft for adoption）
- 适用范围：古建筑、古镇、寺庙、院落、园林和大型室外遗产场景；以 360° 视频为主，同时兼容普通相机和无人机影像
- 证据档案：[RESEARCH-3DGS-LARGE-OUTDOOR-HERITAGE-2026-08-29.md](RESEARCH-3DGS-LARGE-OUTDOOR-HERITAGE-2026-08-29.md)

本文使用以下规范词：

- **必须（MUST）**：不满足则不能以对应质量等级交付；
- **应（SHOULD）**：默认执行，只有书面记录理由时才可偏离；
- **可（MAY）**：按场景、预算和风险选用。

## 1. 核心原则

1. **先定义用途，再定义质量。** 视觉逼真、度量准确、档案可信和实时性能是不同维度，不能用一个 PSNR 或一段好看的漫游视频代替。
2. **3DGS 是表现层，不自动成为测量层。** 用于测绘、病害记录或修缮决策时，必须与受控摄影测量、TLS/LiDAR、GNSS/GCP 或其他可追溯几何基准组成双轨成果。
3. **原始证据不可变。** 原始视频/照片、相机元数据、控制数据和校验和必须长期保存；去模糊、超分、色彩生成和模型压缩都只能是可追溯衍生物。
4. **大场景首先是数据组织问题。** 长视频应按空间连续、语义完整的场景切分，再考虑分块训练、显存卸载或多 GPU。
5. **360° 相机要使用全景感知分区。** 不得未经验证直接套用依赖局部相机视锥的城市级分区策略。
6. **所有结论必须来自固定留出集和可复现实验。** 训练视图指标、随机单图曲线和主观挑图只能用于诊断，不能独立通过验收。

## 2. 交付等级

每个 scene 必须在采集前声明一个主等级，也可同时声明更高等级。

| 等级 | 主要目的 | 3DGS 角色 | 必要的几何依据 | 可宣称内容 |
|---|---|---|---|---|
| V — 视觉展示 | 导览、传播、影视预览、互动漫游 | 主成果 | SfM 内部一致性；可无绝对尺度，但必须明确 | “视觉重建/漫游”，不得宣称测量精度 |
| D — 工程记录 | 建筑记录、空间协调、阶段对比 | 表现层 + 辅助成果 | GCP/检查点、标尺、GNSS 或 TLS/LiDAR；独立精度报告 | 仅可宣称报告中实测的坐标/尺度精度 |
| A — 保护归档 | 长期保存、修缮依据、学术档案 | 可再生的表现层 | 受控摄影测量/TLS/LiDAR、坐标基准、颜色/设备/处理链和长期保存策略 | 需满足机构/项目专项标准，3DGS 不能是唯一档案 |

如果用途未声明，默认只能按 V 级处理。

## 3. 标准工序与门禁

```text
任务定义
  → 现场与许可计划
  → 原始数据入库
  → 抽帧/画质/遮罩
  → SfM、rig 与尺度
  → 场景切分/大场景路由
  → 基线训练与受控试验
  → 固定留出集 + 几何 + 人工 QA
  → 坐标规范化与安全检查
  → 权威归档包 + 发布衍生物
```

任何阶段失败时，必须回到产生问题的最早阶段；不得用更长训练掩盖采集、位姿或尺度失败。

### G0 — 任务、真实性和许可

开始采集前必须记录：

- 场地、对象、负责人、日期、用途等级和目标平台；
- 拍摄许可、人员隐私、无人机/保护区限制和发布许可；
- 是否包含敏感位置、宗教空间、题记、文物细节或可识别人脸；
- D/A 级的坐标系、单位、目标精度、控制与检查方案；
- 预期的场景切分单元和缺失区域处理方式。

**门禁：** 未完成用途/许可声明，不得进入公开发布；D/A 级未声明目标精度和验证方式，不得开始正式采集。

### G1 — 场景切分与采集设计

#### 3.1.1 场景边界

长路线必须优先拆成语义和空间都连续的 scene，例如：

- 单个院落及其门洞；
- 一段连续街巷及两个可识别端点；
- 一座殿/楼及其环绕路径；
- 一条廊道、园路或桥；
- 相邻 scene 间保留足够重叠的“接缝区”。

不得默认把几百秒、跨多个院落/街区且存在长直线位移的 360 视频训练成一个单模型。应在元数据中保留 location → scene → capture → run 的层级，并为相邻 scene 记录连接点。

#### 3.1.2 采集路径

采集必须满足：

- 场景在采集期间尽可能静态；避开密集游客、强风植被、车辆和快速移动阴影；
- 缓慢、平稳运动，避免急转、跑动、滚转和相机贴近表面；
- 形成回环；长走廊/街巷至少在关键节点横向观察或回看，避免纯前向运动；
- 屋檐、檐下、门洞、角点、背阴面、台阶、屋顶和高低差区域增加多高度/多方向补拍；
- 避免曝光泵动、自动白平衡突变、耀斑、雨滴、污渍和运动模糊；
- D/A 级保留颜色卡/灰卡、尺度标尺、控制点和设备校准记录；
- 计划式照片采集应以文化遗产摄影测量指南为基准，保证相邻影像与航带间重叠；360 视频仍须用实际可匹配特征和轨迹连通性验证，不能只按帧率假设重叠。

推荐先拍 30–90 秒代表性 pilot，完整跑通 G2–G9 后再拍全场。

**门禁：** 明显缺少回环、关键立面只从一个方向可见、连续模糊/过曝或遮挡无法通过补拍解决时，正式训练应暂停并重采。

### G2 — 不可变入库与溯源

每次 capture 必须保存：

- 原始媒体文件及 SHA-256；
- 文件字节数、容器/编解码、分辨率、帧率、时长、创建时间；
- 相机/镜头/固件、拼接软件及版本、稳定模式、曝光和白平衡策略；
- 拍摄者、路径说明、天气、光线、人流和异常日志；
- D/A 级的控制点、标靶、GNSS/TLS/LiDAR 原始数据和坐标基准；
- 所有衍生数据与源文件之间的 manifest 关系。

原始文件必须只读保存。若使用第三方拼接、去噪或增强，必须同时保留未处理源和完整参数。

**禁止：** 用 AI 超分、内容感知修补或生成式去遮挡后的图像覆盖原片；把生成纹理当作文化遗产证据。

### G3 — 抽帧、投影和图像质量

360 视频基线应采用：

- 先按时间取得候选帧，再进行清晰度、曝光和相似度筛选；
- 每秒约 3 个候选帧作为 pilot 起点，而非不可变常数；
- ERP 全景默认展开为 8 个透视视图；若小构件/配准覆盖不足，可 A/B 试验 14 个视图；
- 默认裁去底部约 20%，防止采集者、自拍杆和拼接底洞污染；
- 保留 panorama id、时间戳、虚拟视图方向和 rig 成员关系。

筛选器必须输出每帧拒绝原因和分布统计，至少包含：

- 清晰度/运动模糊；
- 过曝、欠曝和动态范围；
- 重复度和时间/空间间距；
- 人员/车辆/植被等瞬态占比；
- 拼接缝、镜头污渍和耀斑。

阈值应从 pilot 的分布和人工标注校准，不能把某一场景的 Laplacian 或像素阈值写成通用标准。

**门禁：** 抽帧后必须人工抽检全部时间段和空间区段；任何关键面若只剩少量、单方向或低质量视图，回 G1/G3。

### G4 — 遮罩与天空

必须：

- 人员、车辆和其他确定性瞬态对象的 mask 同时用于 SfM 特征和 3DGS 训练；
- 记录模型版本、置信度、后处理和 mask 覆盖统计；
- 抽检最小、最大和中位 mask 占比样本；
- mask 不得误删建筑边缘、雕刻、栏杆、匾额和小构件。

室外场景应增加天空处理：

- 优先使用 sky mask；若方法支持，可使用天空模型/天空球；
- 将树梢、飞檐和天空交界作为专门的边界 QA 集；
- 不能仅依靠最终 PLY 的远点/大高斯清理来补救天空训练问题。

对于跨时段采集，可增加植被、强反光和临时设施 mask。任何人工修补必须有版本记录。

**门禁：** mask 明显侵蚀建筑本体，或天空造成大量远距离高斯/漂浮物时，不得进入正式长训练。

### G5 — SfM、rig、坐标与尺度

#### 3.5.1 360 rig

当前稳定基线可继续使用“每张全景展开 8/14 个 PINHOLE，固定同帧相对外参”的 rig 模式；同时应在隔离分支 A/B 测试新版 COLMAP 原生 panorama rig。

匹配至少包含：

- 时间相邻帧的 sequential matching；
- 同一全景各虚拟视图之间的已知/受控 rig 关系；
- 回环和跨路径匹配；数据达到数千视图时可评估词汇树或空间先验；
- 对重复纹理、长廊和相似门窗进行误匹配检查。

必须固定或强约束 rig 相对位姿；相机内参是否优化必须通过 pilot A/B 决定并记录。不能让每个虚拟视图在 BA 中独立漂移成不一致相机。

#### 3.5.2 SfM QA

至少报告：

- 注册图像数与比例；
- 连通分量及各分量规模；
- 每图观测数、track length、重投影误差的分位数；
- 相机中心轨迹、姿态、回环闭合和异常跳点；
- rig 内方向/位置离散度；
- 稀疏点云空间范围、孤岛和异常远点；
- GCP/检查点残差（D/A 级）。

项目目标可将注册率 ≥98% 作为 pilot 的优秀目标、95%–98% 作为需审查区间、<95% 作为默认失败；但高注册率绝不覆盖错误回环、重复纹理错配或异常重投影。只有一个主要连通分量也不等于轨迹正确。

#### 3.5.3 坐标与尺度

- V 级允许相对尺度，但 manifest 必须明确 `metric_scale=false`；
- D/A 级必须使用控制、标尺、GNSS、TLS/LiDAR 或已知建筑尺寸求得并验证度量尺度；
- 坐标系、轴向、手性、单位、原点、地理基准和变换矩阵必须明确；
- 对齐应使用独立检查点验证，不能只报告拟合控制点残差；
- 任何 `unsafe override` 只能产生诊断/preview 产物，不能进入正式 D/A 交付。

当前项目的 up-angle、height-span 等启发式应保留为安全门禁，但必须同时人工查看相机轨迹与代表性渲染；启发式通过不等于坐标正确。

### G6 — 大场景方法路由

方法选择必须由相机类型、场景范围、用途和硬件共同决定：

| 条件 | 首选路线 | 不应做的事 |
|---|---|---|
| 单院落/单建筑，基线可在显存内完成 | 当前 Splatfacto/gsplat 基线 | 过早引入分布式系统 |
| 长 360° 室外轨迹 | 先按院落/街段切 scene，再做 PanoLOG/G²PS 风格的全局粗模 + 几何/梯度分区 PoC | 直接按局部相机视锥切块 |
| 普通相机/UAV 的大型街区 | H3DGS、CityGaussian；VastGaussian 作为论文设计参照 | 把作者 benchmark 当作本项目保证值 |
| 模型正确但单卡 OOM | 先试分辨率/缓存/稀疏梯度和 gsplat；再评估 GS-Scale/CLM-GS | 在位姿、天空或 densification 异常时先堆内存技术 |
| 有稳定多 GPU 基础设施 | H3DGS chunk 并行、CityGaussian、DOGS、Grendel-GS | 未建立单卡正确基线就直接分布式 |
| 需要超大场景实时浏览 | H3DGS/HiGS/streamed SOG 等 LOD/流式路线 | 把渲染加速误当训练质量优化 |
| 需要表面/mesh 或测量 | 2DGS/摄影测量 mesh + TLS/LiDAR 双轨 | 仅从 3DGS 外观推断结构精度 |

#### 3.6.1 PanoLOG PoC 的最低要求

在一段代表性白天 scene 上隔离测试，必须记录：

- 独立环境、精确 commit、许可证和 CUDA/PyTorch/GPU；
- ERP 原图、SfM 转换、深度模型、sky mask 和深度尺度对齐的来源；
- coarse → partition → per-block → merge 各阶段时间、显存、磁盘和失败点；
- 与当前 8-view Splatfacto 在同一固定留出集上的画质、接缝、天空、远景、几何和成本；
- 分块边界处的相机分配与视觉接缝；
- 是否能在 16 GB GPU 或可用计算资源上稳定复现。

在 PoC 通过前，不得替换生产基线。

### G7 — 训练与实验控制

每个正式 run 必须冻结并保存：

- 输入 manifest 和所有文件 hash；
- train/validation/test 列表；
- 代码 commit、补丁、Python/框架/CUDA/GPU 版本；
- 完整配置、随机种子、启动命令、自动重试和 OOM 降级过程；
- checkpoint、TensorBoard/结构化指标、峰值显存、训练时间、磁盘量和高斯数量曲线。

#### 3.7.1 基线优先级

1. 保留当前 Splatfacto-big + SfM 点初始化为 B0；
2. 同一次试验只改变一个主因素；
3. 优先次序：固定评测 → sky mask → 场景切分/分块 → SfM rig A/B → 内存/吞吐；
4. 曝光变化先试双边网格/曝光补偿；只有多时段非受控照片才考虑 WildGaussians/Splatfacto-W；
5. 多尺度浏览试 Mip-Splatting/antialiased；几何任务另开 2DGS 或 mesh 分支。

#### 3.7.2 Densification 与训练停止

- 不设置跨数据集通用的“正确高斯数量”。数量只作为与同场景健康基线比较的诊断量；
- 必须记录 densification、split/clone、prune、opacity reset 和 cull 的时间序列；
- 高斯数突然下降、长期不增长、导出数量与训练末端不一致均视为异常；
- 当前项目的“低于 2M”只能作为告警，不是通用验收线；
- 训练步数由固定留出集的聚合曲线、视觉稳定性和成本共同决定；不得从随机图像的 step 曲线宣称 plateau；
- OOM 后自动降采样可以保留诊断结果，但正式发布前必须明确标记降级发生及其影响。

### G8 — 评测与验收

#### 3.8.1 固定留出集

每个 scene 必须在 SfM/训练前生成确定性 split：

- 建议留出 10%–15% 的 panorama 作为 test 起点；
- 360 panorama 的全部虚拟视图必须属于同一 split，防止同帧泄漏；
- 不能简单每 N 帧均匀抽取后让近乎重复的相邻帧分属 train/test；应按空间段、视点簇或短连续片段分层留出；
- 覆盖入口、回环、长廊、院落中心、檐下、天空边界、远景、反光材质和困难遮挡；
- split 文件必须入 manifest，后续实验不得变化。

#### 3.8.2 新视角质量

在固定 test 集上至少报告：

- PSNR、SSIM、LPIPS 的 mean、median、P05/P95 和逐图结果；
- 固定检查图组成的 contact sheet；
- 按空间区段、距离、天空占比和难例类别分组的指标；
- 多个 checkpoint 的同集聚合曲线和不确定性/波动范围。

停止训练必须基于连续多个 checkpoint 在同一留出集上改进低于项目预设容差，同时困难区没有退化；容差应由 pilot 的重复运行噪声确定，而不是使用未经验证的通用 dB 阈值。

#### 3.8.3 几何与位姿

V 级至少检查：

- 轨迹连续、回环、地面/墙体、垂直线、门洞、屋檐和薄结构；
- 漫游中无明显拉伸、漂浮、双影、穿墙和视点依赖跳变。

D/A 级还必须报告：

- 独立检查点 RMSE 与分方向残差；
- 有参考轨迹时的 ATE/RPE；
- 与 TLS/LiDAR/摄影测量 mesh 的 Chamfer、点到面距离、precision/recall/F1 或项目指定指标；
- 距离误差热图和关键构件剖面；
- 误差是否满足 G0 声明的用途级目标。

不得使用训练图像 PSNR 推导几何精度。

#### 3.8.4 视觉和遗产专项 QA

必须人工审查：

- 飞檐、斗拱、瓦当、栏杆、窗棂、题刻、台阶和薄结构；
- 天空边界、树梢、反光琉璃瓦、水面和阴影；
- 人、车、自拍杆、拼接缝和地面孔洞；
- scene/块边界的颜色、密度、几何和运动连续性；
- 颜色是否因外观模型而明显偏离原始受控照片；
- 是否存在 AI 增强或人工修补，以及展示端是否明确标记。

#### 3.8.5 性能与规模

同一硬件和渲染分辨率下报告：

- 总时间与各阶段时间；
- 峰值 GPU/CPU 内存、磁盘、模型大小和高斯数；
- 首屏时间、平均/低分位 FPS、LOD/流式加载行为；
- 训练/渲染发生的降采样、量化和剔除；
- 与基线的质量—成本 Pareto，而非只报最快或最高 PSNR。

### G9 — 坐标规范化、清理和发布

正式导出前必须：

- 明确输入坐标、发布坐标、轴向、手性、单位、原点和完整变换链；
- 用相机、控制点和代表性构件验证变换；
- cull 远点、大尺度高斯、低透明度点时保存规则、数量前后变化和可视化差异；
- 不允许以手工旋转“看起来正确”替代变换矩阵和验证；
- 不允许正式成果绕过坐标安全门禁。

#### 3.9.1 权威归档包

每个通过验收的版本至少包含：

```text
scene-release/
├── manifest.json/yaml
├── provenance/          # 原始媒体 hash、许可、设备、代码和环境
├── splits/              # 固定 train/validation/test
├── cameras/             # COLMAP、transforms、rig 和坐标说明
├── controls/            # D/A 级控制与检查报告
├── model/
│   ├── source.ply       # 全精度权威 3DGS 交换副本
│   └── model-metadata.*
├── qa/                  # 指标、逐图结果、contact sheets、几何报告
├── preview/             # 固定相机预览和漫游
└── derivatives/         # 可再生成的 SPZ/SOG/glTF/引擎包
```

原始媒体可位于 location 级不可变库，但 manifest 必须能通过 hash 定位。

#### 3.9.2 发布格式政策

- 全精度 PLY + 相机/变换 + manifest 作为当前权威交换副本；
- SPZ、SOG 和 streamed SOG 作为压缩/流式运行时衍生物；
- `KHR_gaussian_splatting` 在正式批准和工具互操作成熟前标记为候选格式；
- 每种转换都必须验证高斯数量、坐标轴、尺度、旋转、球谐、透明度、外观差异和查看器兼容性；
- 不得只保存有损运行时格式。

## 4. 当前 GSDB 的符合性与缺口

| 项目 | 当前状态 | 规范判断 | 动作 |
|---|---|---|---|
| location → scene → capture → run 分层 | 已建立 | 符合 | 保持 |
| 源文件 hash、配置、日志、manifest | 已有基础 | 基本符合 | 扩展许可/设备/颜色/控制字段 |
| 360 投影 8 视图、14 视图回退、20% 底裁 | 已实现 | 与官方指南一致 | 保持，以 pilot A/B 校准 |
| 人员 mask 同时用于 COLMAP/训练 | 已实现 | 符合 | 增加误删抽检和版本记录 |
| sky mask/天空模型 | 缺失 | 主要缺口 | P0/P1 增加并 A/B |
| 固定相对外参的虚拟 rig | 已实现 | 方向正确 | 对新版 COLMAP 原生 panorama rig 做隔离 A/B |
| 长 360 场景分区 | 未形成专用方案 | 主要缺口 | 先按院落/街段拆 scene，再做 G²PS PoC |
| 固定空间留出 test 集 | 不充分 | 阻断严肃收敛结论 | P0 修复评测设计 |
| eval curve | 混合 `eval*` tag 的逐 step 值 | 不能证明 plateau | 固定图像聚合、逐图保存、区段分组 |
| metric scale / GCP / LiDAR | 当前云岫无 | 只能 V 级 | D/A 级采集必须新增 |
| 坐标安全门禁 | 已有，但可 unsafe override | 诊断可用，正式交付不足 | 正式发布禁止 override |
| OOM 自动 downscale | 已发生 | 可作诊断降级 | 必须显式标记；先查 densification/导出异常 |
| 最终高斯数 | 云岫仅 19,184 | 对该大场景明显异常 | P0 诊断 split/prune/cull/export 链，不直接加步数 |
| LOD/流式发布 | 缺失 | 大场景发布缺口 | 质量通过后生成 streamed SOG/H3DGS 等衍生物 |

当前云岫 run 只能标记为 `pipeline_proof / V-preview / unsafe-coordinate`，不得作为 D/A 级正式参考模型。

## 5. 推荐实施顺序

### P0 — 在下一次长训练前完成

1. 建立 panorama 粒度、空间分层的固定 test split；修复 eval 聚合与 checkpoint 对照。
2. 查明最终 19,184 高斯的来源：训练末端数量、densification、prune/cull、OOM 重试和 export 各阶段逐一核对。
3. 将 `unsafe override` 产物限制为 preview，正式发布必须重新对齐并通过坐标检查。
4. 把当前 427 秒长路线拆成院落/街段/廊道级 scene，记录重叠接缝。

### P1 — 建立室外质量基线

1. 加入 sky mask，并在同一 scene 上与当前人员 mask 基线 A/B。
2. 增加固定困难视角 contact sheet：飞檐、瓦片、天空边界、反光、树梢、门洞、地面。
3. 对 COLMAP 新版 panorama rig 与当前 3.8 自维护 rig 做隔离 A/B。
4. 更新正式采集表：回环、多高度、颜色/曝光、标尺/GCP、天气、人流和许可。

### P2 — 大场景与交付试验

1. 在单个代表性白天 scene 上完成 PanoLOG/G²PS PoC；不直接迁移全项目环境。
2. 若模型正确但仍 OOM，依次评估 gsplat 稀疏/内存选项、GS-Scale/CLM-GS；有多 GPU 时再评估 H3DGS/CityGaussian/DOGS。
3. 建立 PLY → SPZ/SOG/streamed SOG/glTF 候选格式的转换与回归 QA。

### P3 — 度量与遗产档案

1. 选一个 D 级 pilot，引入 GCP + 独立检查点，最好增加 TLS/LiDAR 小区域真值。
2. 建立尺度、坐标、误差热图和关键构件剖面报告。
3. 根据负责机构采用 Historic England/ICOMOS 或当地测绘与文保标准，形成项目专项精度条款。

## 6. 最小实验矩阵

所有实验使用同一输入 hash、同一 SfM（除非该实验专门比较 SfM）、同一 split、同一 checkpoint 和同一硬件记录。

| ID | 只改变的因素 | 目的 | 通过条件 |
|---|---|---|---|
| B0 | 当前 Splatfacto-big | 固化真实基线 | 可复现；固定 test 指标和 QA 完整 |
| B1 | 评测实现 | 验证旧 eval curve 是否失真 | 每 checkpoint 固定图像一致、聚合稳定 |
| B2 | + sky mask/天空模型 | 去除天空远点与边界伪影 | 困难集改善，建筑边缘无侵蚀 |
| B3 | 新版 COLMAP panorama rig | 比较位姿与连通性 | 回环/rig/重投影改善且无新错配 |
| B4 | scene 切分 + 重叠 | 验证语义分段 | 每段稳定、接缝可控、总成本下降 |
| B5 | PanoLOG/G²PS | 验证全景大场景分区 | 同 test 集质量/远景/接缝/成本形成可接受 Pareto |
| B6 | gsplat/内存扩展 | 解决确定性 OOM | 质量无显著回退，显存/时间收益可复现 |
| B7 | GCP/TLS/LiDAR | 建立 D 级几何链 | 达到 G0 声明精度，独立检查通过 |

不得把 B2–B7 多项同时改变后归因于单一方法。

公开 skill 中，`Awesome-Gaussian-Skills` 的工程指南、训练调试器和实验规划器可作为知识索引，但不宜直接成为 GSDB 标准。建议后续创建一个版本化的 `gsdb-heritage-360-workflow` 项目 skill；其职责应是执行本文，而不是发明新阈值。

## 8. 验收清单

### 数据与溯源

- [ ] 用途等级、许可、对象和目标平台已声明

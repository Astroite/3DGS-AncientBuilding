# UI 风格探索与设计交付

优先级 P0 · 关联 UI-01～UI-04、I-01/I-04、V-03、E-01～E-03。

用户认为当前 UI 不够美观，因此现有界面仅保留为功能原型。探索阶段先形成可比较的静态稿，不启动应用或训练，不预先限定 Tk、Web、Qt、WinUI 等技术。

## 三个方向

| 方向 | 布局与视觉 | 主要工作方式 | 需要观察的取舍 |
| --- | --- | --- | --- |
| A 深色专业工作台 | 中性石墨灰、克制的青绿强调；大视口、薄工具栏、可折叠检查器 | 长时间观察与精细编辑 | 紧凑不等于拥挤，参数不能挤压视口 |
| B 极简创作工具 | 温和浅色、清晰字体、留白；导入/训练/编辑分阶段显示 | 较少参数下完成主要流程 | 避免步骤切换遮住重要训练状态 |
| C 影像检查工作台 | 深色影像画布、图片条、源图与渲染并排、集中状态区 | 质量诊断和同视角比较 | 双视图仍需足够尺寸，避免缩成缩略图 |

三套方案使用相同场景示意、相同图片数和训练状态，防止内容差异影响选择。模拟进度和示意画面必须标注，不能当成实际结果。

## 第一阶段交付

每个方向交付：

1. 1920×1080 主工作台静态稿：训练中、图片导航、核心状态、主要按钮。
2. 同尺寸导入检查稿：images/COLMAP/masks、匹配摘要、错误定位和开始入口。
3. 一页视觉样式说明：颜色角色、字体层级、间距、图标、选中与焦点状态。
4. 一页取舍：典型用户、信息密度、1280×800 小窗口如何收缩。

本阶段已按用户 DEV-02 请求交付 `direction-a-workspace.svg`、`direction-a-import.svg` 等六张本地 SVG，保存在 `design/deliverables/`。三份方向说明分别合并样式、组件、小窗口规则和取舍；[交付与比较](deliverables/COMPARISON.md)提供完整索引与 DEV-03 评审输入。没有生成渲染程序或启动应用。

## 方向选定后的细化

- 完整页面：空项目、导入检查、准备/等待、训练、暂停、失败、恢复、模型编辑、导出与重开项目。
- 功能区：相机/图片双向定位、掩膜覆盖、损失与资源信息、同视角对比、选区与裁剪、场景变换。
- 交互说明：按钮禁用的原因、非阻断提示、需要用户处理的错误、长任务取消和保存反馈。
- 统一设计规范：字体、颜色、间距、圆角/边框、图标、控件尺寸、键盘焦点、选中/悬停/错误/禁用。
- 为 1280×800 与 1920×1080、100% 与 150% 缩放给出布局规则。设计画布覆盖不等于已在真实 DPI 环境验收。

内容分组和字体层级参考 [Windows 布局指南](https://learn.microsoft.com/en-us/windows/apps/design/basics/content-basics) 与 [字体指南](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography)，不意味着选用微软 UI 框架。

## 评审清单

| 评审项 | 合格判断 |
| --- | --- |
| 主次关系 | 第一眼知道当前阶段、模型在哪里、接下来能做什么 |
| 视口面积 | 面板能够收缩；模型检查不被长表单和路径输入挤压 |
| 对比检查 | 源图与渲染清楚对应；同步缩放、平移与当前视角有明确反馈 |
| 操作语义 | 新实验、继续训练、保存项目、检查点、导出不混淆 |
| 状态覆盖 | 等待 GPU 不能伪装成训练；失败能指出原因和下一步 |
| 信息可读 | 数字层级、中文字体、长文件名、遮罩极性和验证分组清晰 |
| 编辑反馈 | 已选数量、删除影响、裁剪框、变换方向和撤销可理解 |
| 风格一致 | 不是默认控件堆叠，也不是每块面板各自一套样式 |

三方向分别给出“符合/待改/不适用”及依据。用户选择主方向后记录 D-04；在选择之前，不能把某套标为已获认可。

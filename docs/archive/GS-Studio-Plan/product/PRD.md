# 产品需求说明

> **历史下游范围（2026-09-13）。** 本文从 RealityScan 输出开始的首版定义，已由 [APP 项目路线图](../../../architecture/GS-STUDIO-PROJECT-ROADMAP.md)扩展为采集到交付的全流程 GUI；原 I/T/V/E/O 需求仍作下游功能依据。本文后续的“首版排除”和“尚未决定”均描述当时状态。

版本 0.1 · 2026-09-13 · 目标范围已据用户要求整理；未决事项见 [决策清单](../planning/DECISIONS-AND-RISKS.md)。

## 问题与目标

用户已有 RealityScan 前置重建，只需要可靠的本地高斯训练与可视化检查。Postshot 的导出和自动化档位限制，以及不需要的视频等能力，使现有方案的成本与需求不匹配。目标是将数据导入、训练观察、基础清理和模型交付连成清晰工作流；不以克隆商标、界面或私有格式为目标。

主要用户：当前 Windows + NVIDIA 工作区的操作者，处理街景和室内片段，了解 images/COLMAP 的概念，但不希望依赖命令行完成日常训练。未来 Agent 自动化入口为 P1。

## 用户流程

| 场景 | 用户意图 | 产品结果 |
| --- | --- | --- |
| US-01 导入 | 使用已重建的数据开始 | 看到图片、相机、稀疏点和遮罩检查摘要，确认可训练输入 |
| US-02 训练 | 选择合理预算并随时掌握状态 | 直接使用已有位姿训练，可以暂停、继续、结束或恢复 |
| US-03 检查 | 判断细节、遮挡与新视角问题 | 自由观察实时模型，与对应源图同步查看 |
| US-04 编辑 | 清除漂浮点、截取目标区域、摆正方向 | 在独立快照上编辑，可以撤销和保留原始结果 |
| US-05 交付 | 下次继续工作或交给其他查看器 | 项目可恢复，Gaussian PLY 可导出并核验 |

## 首版范围

P0 包括完整 I/T/V/E/O 功能，以及 UI 风格探索和正式视觉规范。详见 [需求清单](REQUIREMENTS.md)。

P1：ROI 训练、多实验同视角比较、精细画笔/套索选择、顺序队列、Agent 自动化、SPZ/SOG 等压缩格式与独立查看器导出。

首版排除：视频读取/抽帧/剪辑/全景展开、SfM 与相机跟踪、重建修复、多场景拼接、视频渲染/动画时间线/4DGS、网格生成、UE/AE 插件、云训练、账户与团队协作、在线发布、`.psht` 兼容及完整复制 Postshot 算法。

## 成功标准

- 用户能通过界面完成从合格输入到 PLY 交付的全部首版流程。
- 图片、位姿、遮罩和分组错误能在训练前定位；不能静默修改输入或让验证数据泄漏进训练。
- 训练中能判断当前模型质量，控制暂停/恢复，并清楚知道输出是否真实完成。
- 编辑可撤销，保存重开和导出重载保持相同结果。
- 用户认可正式 UI 方向；当前功能原型不满足此项。
- 功能验收、真实画质验收和性能定级独立记录，不以短训练代替画质结果。

## 默认约束与开放决策

确定：本地离线、Windows + NVIDIA、一个已选模型或分段、正式 SH3 与光度补偿、原始数据只读、保留输入分组、不依赖 Postshot 许可。

首版最低输入兼容基线：JPG/PNG、COLMAP BIN/TXT、PINHOLE/SIMPLE_PINHOLE；不支持的相机明确阻断，前置导出去畸变结果。

尚未决定：正式 UI 风格与框架、训练引擎及复用方式、项目存储策略、性能阈值和算法选择。此文件不进行架构设计。

当前只允许规划与静态设计资料工作。测试与应用验证保持暂停，直到用户另行明确要求。

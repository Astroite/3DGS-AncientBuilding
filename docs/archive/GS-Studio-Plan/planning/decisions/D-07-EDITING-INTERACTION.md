# D-07：采用拖拽手柄与数值输入

- 日期：2026-09-13
- 状态：交互部分已接受；底层拾取与可见性算法已有评估输入、待决策
- 决定者与依据：用户在 DEV-04 规划中选择“拖拽手柄＋数值输入”，并要求实施包含此选择的完整计划。
- 关联需求与任务：E-01～04、UI-02～04；DEV-04、DEV-15、DEV-16。
- 替代的既有决定：没有；不再把现有原型的主要数值输入当作正式交互基线。

## 问题与选项

数值输入优先便于精确填写，但缺少在视口中直接调整模型的过程。拖拽手柄＋数值输入同时提供直观空间操作与精确调整，需设计同步预览、选中轴、提交与撤销反馈。两者均未在本阶段做性能或实现成本评测。

## 已接受的决定

- 裁剪提供可视化面/角点手柄、中心和尺寸输入，以及框内/框外保留预览。
- 平移提供轴与平面手柄；旋转提供轴向环；缩放只提供统一倍率与中心手柄。
- 高亮轴和平面并同步对应字段。拖拽松开或确认数值形成一次提交；Esc 取消当前未提交手势。
- 裁剪先调整预览框，框体调整有预览撤销；应用后在模型历史中记录一次裁剪。活动训练和原始快照不受编辑影响。
- 删除、裁剪、变换支持撤销重做，编辑结果另存版本；世界/局部坐标、朝上和地面操作有明确预览与确认。

详细设计见 [DEV-04 索引](../../design/specification-a/README.md)与[交互说明](../../design/specification-a/INTERACTIONS.md)。上述交互细节已随DEV-04获用户设计认可，不表示真实手柄已实现。

## 保持待定的事项

非穿透选择仍需明确最终可见性与拾取算法；原型的最近高斯中心近似不能自动成为正式承诺。透明贡献、深度判定、手柄求交和渲染实现由后续技术评估处理；本记录不设算法或框架。

D-07 不整体标为关闭：用户交互方式已确定，技术部分由 DEV-05/DEV-15 继续评估。没有运行测试、应用验证或训练，也不解除 D-02。

## DEV-05 评估输入（未接受为算法决定）

[静态比较](../../research/technical-evaluation/CANDIDATE-COMPARISON.md)确认本地非穿透选择是每像素最近高斯中心近似；LichtFeld有选区、节点范围和深度筛选代码，但不能据此断言采用透明贡献拾取。建议先明确用户可观察规则，再评估手柄求交/渲染可见性实现。独立快照身份与活动训练隔离仍是必要条件；本轮不指定算法、不关闭D-07。
